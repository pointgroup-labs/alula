# Market Methods

The market contract contains a wide range of methods to manage markets, interact with assets, and manage user positions. They can be categorized as follows:

## Administrative & Governance Functions

These functions typically require authorization checks (`require_admin`, `require_owned_and_admin`, `require_deployer`).

<table><thead><tr><th width="320.36358642578125">Function</th><th>Purpose</th></tr></thead><tbody><tr><td><code>__constructor</code> (not accessible directly, invoked via Market Manager)</td><td>Initializes the market with its core parameters (admin, oracle, name, etc.).</td></tr><tr><td><code>update_market</code></td><td>Changes core market parameters (<code>max_positions</code>, <code>min_collateral_value</code>). Only on owned markets.</td></tr><tr><td><code>update_market_status</code></td><td>Changes the operability status of the market's operations. Only on owned markets.</td></tr><tr><td><code>initialize_pool</code></td><td>Creates a new loan pool for a specific asset (token) within the market.</td></tr><tr><td><code>initialize_multiply_pair</code></td><td>Registers a new pair of pools (deposit/borrow) for leveraged positions.</td></tr><tr><td><code>queue_in_pool_config_update</code></td><td>Starts the process of updating a pool's configuration by adding the new config to an update queue. Only on owned markets.</td></tr><tr><td><code>apply_pool_config_update</code></td><td>Finalizes a pool's configuration update after its required queue period has passed. Only on owned markets.</td></tr><tr><td><code>cancel_pool_config_update</code></td><td>Cancels a pool's configuration update if it exists in an update queue. Only on owned markets.</td></tr><tr><td><code>redeem_accumulated_market_fees</code></td><td>Allows the admin to withdraw accumulated market fees.</td></tr><tr><td><code>redeem_accumulated_host_fees</code></td><td>Allows the deployer to withdraw accumulated host (platform) fees.</td></tr></tbody></table>

## User Lending & Borrowing Functions

These are the primary financial interactions, generally requiring the user's authorization (`user.require_auth()`).

<table><thead><tr><th width="319.90911865234375">Function</th><th>Purpose</th></tr></thead><tbody><tr><td><code>deposit</code></td><td>Supplies tokens to a loan pool, earning interest.</td></tr><tr><td><code>deposit_into_earn_obligation</code></td><td>Supplies tokens to a pool under an <em>isolated</em> obligation that prohibits borrowing, earning interest.</td></tr><tr><td><code>borrow</code></td><td>Takes out a loan from a pool against existing collateral.</td></tr><tr><td><code>repay</code></td><td>Returns borrowed tokens to a pool, reducing debt.</td></tr><tr><td><code>withdraw</code></td><td>Removes deposited tokens from a pool.</td></tr><tr><td><code>withdraw_from_earn_obligation</code></td><td>Removes deposited tokens from the isolated <em>Earn</em> obligation.</td></tr><tr><td><code>add_collateral</code></td><td>Adds tokens to a pool as collateral (does not earn interest but improves health).</td></tr><tr><td><code>remove_collateral</code></td><td>Removes collateral from a pool (limited by obligation health).</td></tr><tr><td><code>deposit_with_leverage</code></td><td>Opens a leveraged position by depositing a margin, flashing-loaning, and swapping tokens.</td></tr><tr><td><code>withdraw_from_leveraged</code></td><td>Withdraws tokens from a leveraged position without affecting the leverage.</td></tr><tr><td><code>flash_loan</code></td><td>Issues a temporary, uncollateralized loan to a contract that must be repaid within the same transaction.</td></tr><tr><td><code>liquidate</code></td><td>Repays a borrower's debt (a service function) whose position has become unhealthy, receiving discounted collateral in return.</td></tr><tr><td><code>cover_obligation_bad_debt</code></td><td>Covers bad debt within a user's standard obligation, potentially socializing remaining loss.</td></tr><tr><td><code>distribute</code></td><td>Permissionless method that transfers accrued take rate and net operation fees to the configured beneficiary lists and resets internal accumulators.</td></tr></tbody></table>

## Read-Only / View Functions

### **Core State Variables (Instance Storage)**

These functions do not modify the contract's state but return information.

<table><thead><tr><th width="320.36358642578125">Function</th><th>Purpose</th></tr></thead><tbody><tr><td><code>get_global_state</code></td><td>Returns all global market configuration settings.</td></tr><tr><td><code>get_user_multiply_pair_obligation</code></td><td>Returns the user's current multiply pair obligation details (deposits, borrows).</td></tr><tr><td><code>get_user_earn_obligation</code></td><td>Returns the user's current <em>Earn</em> obligation details (deposits only, since borrows are not allowed).</td></tr><tr><td><code>get_user_obligation</code></td><td>Returns the user's current plain obligation details (deposits, borrows).</td></tr><tr><td><code>get_pool</code></td><td>Returns the current state of a specific loan pool (supply/borrow rates, etc.).</td></tr><tr><td><code>get_pool_asset_oracle_price</code></td><td>Returns the current price of a pool's underlying asset from the oracle.</td></tr><tr><td><code>get_all_pools</code></td><td>Returns a vector of all registered pool addresses.</td></tr><tr><td><code>get_all_obligations</code></td><td>Returns a vector of all obligations that exist. In the future, <code>obligation seed</code> will also be included.</td></tr></tbody></table>

### **Global/Config Variables**

These variables store the global, contract-wide settings and are crucial for the market's operation. They are stored in Instance Storage and share a common TTL.

<table><thead><tr><th width="183.0909423828125">DataKey</th><th width="163.36358642578125">Type</th><th>Description</th></tr></thead><tbody><tr><td><code>Admin</code></td><td><code>Address</code></td><td>The Stellar address of the Market Administrator, possessing privileged control over updates (on owned markets), fee redemption, and market updates (on owned markets).</td></tr><tr><td><code>Name</code></td><td><code>String</code></td><td>The descriptive name of the lending market contract.</td></tr><tr><td><code>Oracle</code></td><td><code>Address</code></td><td>The contract address of the SEP-40 Price Oracle used to determine collateral and borrowed asset values for health checks and liquidations.</td></tr><tr><td><code>DeployerHost</code></td><td><code>Address</code></td><td>The address of the platform Deployer/Host entity, which is authorized to redeem host-side operational fees (applies only to the Market Manager contract).</td></tr><tr><td><code>MarketStatus</code></td><td><code>MarketStatus</code></td><td>The current operational state of the market: <code>Active</code> (all allowed), <code>BorrowFrozen</code>, <code>DepositFrozen</code>, or <code>Frozen</code> (all prohibited).</td></tr><tr><td><code>MaxPositions</code></td><td><code>number</code></td><td>The maximum number of distinct assets (deposits/borrows) allowed within a single user <code>Obligation</code>.</td></tr><tr><td><code>MinCollateralValue</code></td><td><code>number</code></td><td>The minimum collateral value required in an obligation to maintain any active borrows.</td></tr><tr><td><code>UpdateInQueuePeriod</code></td><td><code>optional(number)</code></td><td>If <code>Some(N)</code>, the market is owned (governable), and updates must wait N ledgers in a queue. If <code>None</code>, the market is ungoverned, and, hence, cannot be updated. This value cannot be updated by the admin.</td></tr></tbody></table>

### **User/Core Data Variables**

#### **Shared Persistent Data (Global Lists)**

<table><thead><tr><th width="182.636474609375">DataKey</th><th width="213.3636474609375">Type</th><th>Description</th></tr></thead><tbody><tr><td><code>AllPools</code></td><td><code>Vec&#x3C;Address></code></td><td>A list of the contract addresses for all registered loan pools in the market.</td></tr><tr><td><code>AllObligations</code></td><td><code>Map&#x3C;ObligationKey, ()></code></td><td>A set of all active <code>ObligationKeys</code> (user addresses and optional seeds) that have a position in the market.</td></tr><tr><td><code>AllMultiplyPairs</code></td><td><code>Vec&#x3C;MultiplyPair></code></td><td>A list of all registered leveraged trading pairs (e.g., [Deposit Pool A, Borrow Pool B]).</td></tr></tbody></table>

#### **Individual Persistent Data (Entity Records)**

<table><thead><tr><th width="292.181884765625">DataKey</th><th width="132.2728271484375">Type</th><th>Description</th></tr></thead><tbody><tr><td><code>Pool(Address)</code></td><td><code>Pool</code></td><td>The data structure for a single loan pool, keyed by the pool's contract <code>Address</code>.
